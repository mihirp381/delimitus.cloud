# console

The SSC admin console (SSC-057), decision 018. React 19, Vite 8, TanStack Router (file routes) and
TanStack Query, with an API client generated from `docs/api/openapi.json`. Node 22.22.2+, 24.15+
or 26+ (jsdom's range); CI uses Node 24.

| Path | What |
|---|---|
| `src/api/` | `schema.d.ts` (generated, committed), `client.ts` (bearer token, `Idempotency-Key` on writes, problems become `ApiProblem`), `grants.ts` (sharing changes with `If-Match` and the 412 retry), `directory.ts` (group and person lookup), `lifecycle.ts` (kill switch, enable, owner transfer, rollback), `audit.ts` (filters and export), `approvals.ts` (reading request payloads), `cell.ts` (the cell, usage, health and database types and how their figures are worded), `warm.ts` (the warm option's cost and change), `connections.ts` (data connections: add, change, link to an environment, and the `exceed_ceiling` ask), `timers.ts` (pause, resume, run now, runs), `egress.ts` (allow and remove internet hosts), `github.ts` (the connected repository; NOT_FOUND reads as none), `promote.ts` (promote, then deploy the release the build made). |
| `src/tokens/` | Colour, type, radius, spacing, shadow and layout tokens, matched to the landing page (`landing/index.html`): its accent, tone colours, font stacks and spectrum, each with a dark counterpart. Hex literals live only in `primitives.ts`; `tokens.css` is generated from them. Components and `styles.css` use only `var(--ssc-*)`. |
| `src/auth/` | `oauth.ts` (sign-in through the auth host as the OAuth client `ssc-console`, decision 029: S256 PKCE, state and `iss` checked), session (tokens in memory only, refreshed a minute before the access token expires; a pasted dev token may be copied to `sessionStorage`), the dev token login, and `isAdmin`, the one place that decides which admin-only screens to show (to callers whose `whoami` role is `admin`). |
| `src/routes/` | `/login`, `/auth/callback` (the auth host's answer), `/` (inventory), `/apps/$appId` (environments, who has access, share, rollback and admin actions), `/apps/$appId/kill-switch/$runId` (one kill switch run: its mode, state, total and each step's times, read again while it runs; linked from the admin actions' result and from the audit log's kill switch rows), `/approvals` (read-only list), `/connections` (the data connections the caller may see; org admins add and change them, and a connection's address is sent once and never kept, cached or shown), `/egress` ("Internet access": the fixed outbound IP to copy, the allowed hosts, and for org admins the catalogue to pick from, adding with the high-risk tick, and removing), `/audit` (search and export), `/environment` ("Your environment", admins only: the fixed outbound IP to copy, the parts created when first needed with what asked for each and what each adds a month, the database's places and the bigger-database step, the warm option (SSC-092: which production apps and whether the gateway stay at one instance, suggested where use and cold starts say so, the cost shown before saving and sent with the change, and the gateway offered in the same step), and each app's use this month; never a bill). `src/routeTree.gen.ts` is generated by the router plugin and committed. |
| `src/app-detail/` | The app page's share dialog, rollback, admin-only actions, and each environment's state (asleep is normal), use this month and database (`Running.tsx`); each environment's data connections and timers, read only when their section is opened (`EnvConnections.tsx`, `Timers.tsx`); the connected repository (`Repository.tsx`); one kill switch run, shared by the admin actions and the run's own page (`KillSwitchRun.tsx`); and promote to production, which builds what preview runs and then offers to deploy the release it made (`Promote.tsx`). Builder-only actions are shown to everyone and the API's refusal is shown; admin-only ones are hidden from others. |
| `src/components/` | Button, Badge (the status pill), Table (a card with an empty state that says what to do next), Dialog, ConfirmAction (type the slug to confirm, or one click for what is not destructive), ProblemNotice, Phrases (short phrases that each stay on one line), Brand (the mark, the product name and the spectrum rule), PageHeader (title, status, one line of purpose, the page's actions), EmptyState. |
| `test/` | Vitest: tokens and contrast, the client, the screens against a fake API, sign-in (PKCE, the callback's checks, refresh scheduling, sign-out), and the dev login's absence from production builds. |
| `e2e/` | Playwright tests against Postgres and the real API in Docker: sharing (`smoke.spec.ts`), approvals and the audit log (`admin.spec.ts`), the share dialog and the kill switch (`lifecycle.spec.ts`). |

## Commands

```
npm ci
npm run dev          # Vite on :5173; /v1 is proxied to SSC_API_URL (default http://127.0.0.1:8000)
npm run typecheck
npm test
npm run build        # production build, without the dev login
npm run gen:api      # after docs/api/openapi.json changes; CI fails on a stale client
npm run gen:tokens   # after changing src/tokens/*.ts; CI fails on a stale tokens.css
npm run e2e          # needs Docker; see below
```

## Against a local API

```
uv run python tools/dev_stack.py up --dsn postgresql://postgres@127.0.0.1:5432/postgres
uv run python tools/dev_stack.py serve --port 8000
uv run python tools/dev_stack.py token          # paste this into the console's sign-in page
SSC_API_URL=http://127.0.0.1:8000 npm run dev
```

The token sign-in form exists only in `npm run dev` and in builds made with
`VITE_SSC_DEV_LOGIN=1`; `test/devlogin-absent.test.ts` checks the build output.

## Production sign-in

"Continue with your work account" sends the person to the auth host's `/authorize` (decision 029)
and back to `/auth/callback`, which exchanges the code at `/token`. The build reads two settings:

| Variable | Default | What |
|---|---|---|
| `VITE_SSC_AUTH_URL` | `https://auth.delimitus.com` | The auth host's origin; also the `iss` the callback must carry. |
| `VITE_SSC_API_AUDIENCE` | `https://api.delimitus.com` | The resource asked for, the API's user audience (`SSC_API_USER_AUDIENCE`). |

In production the console is served at `https://console.delimitus.com` by `packages/ssc_console_host` (its Dockerfile runs `npm ci && npm run build` with these two settings), and the control entry sends `/v1` on that host to the API; see "Console" in `infra/README.md`.

The auth host must know the console's origin as `SSC_CONSOLE_URL`: its client `ssc-console`
redirects only to `<SSC_CONSOLE_URL>/auth/callback`, and `/token` and `/revoke` answer CORS for that
origin alone. Tokens live in memory, so a reload asks the auth host again (its own session cookie
skips the email step). Sign-out calls `/revoke`.

While a signed-in page is on show the shell asks `/v1/whoami` every 4 seconds
(`WHOAMI_EVERY_MS` in `src/routes/_authed.tsx`). A 401 there, as for a person deactivated in the
directory, signs the console out and opens the login page, within 5 seconds.

## End-to-end test

`npm run e2e` runs `e2e/run.mjs`: it starts `e2e/compose.yaml` (Postgres 18 and the API built
from `e2e/api.Dockerfile`) under a random project name and host port, mints a token with
`dev_stack.py token` and an operator token for the directory, builds the console with the dev
login, runs Playwright, and removes the containers. Install the browser once into `node_modules`:

```
PLAYWRIGHT_BROWSERS_PATH=0 npx playwright install chromium
```

## Dependencies

Exact versions only. `.npmrc` sets `before=` to a date at least 7 days back, so npm resolves
nothing newer; move it forward when upgrading. CI also runs `tools/npm_lock_age_check.py` on
`package-lock.json`. Never commit `node_modules`.
